# Solar RP (code name GAGE-MP)

Solar RP is its own GTA V multiplayer platform: launcher (`SolarLauncher.exe`, shown to players as "Solar Launcher"), in-game engine (`gage_mp.dll`), the game server (the live one is SOL; LUNA and TERRA are planned) and master list, and an open protocol (docs/ENGINE-PLAN.md). Domain: solar-rp.com.

Naming (renamed from GAGE-MP on 2026-11-01): every string a player or admin sees says Solar RP / Solar Launcher. The internal identifiers keep the old name on purpose, because renaming them breaks upgrades, the launcher -> engine handoff or the integrity check: the installer AppId, `gage_mp.dll`, `gageinjector.dll`, `gage_loader.dll`, `gage_launch_shim.dll`, `HKCU\Software\GAGE-MP` and its value names, `gage_mp.cfg`, `gage.log`, the `%LOCALAPPDATA%\GAGE-MP` data folder, the single-instance mutex and window class, `gage::` namespaces, CMake target names (the launcher target `GAGE-MP` has OUTPUT_NAME `SolarLauncher`), the `/GAGEUPDATE` installer switch, the `gage-mp://` link scheme and the protocol identifiers. The brand images (`brand/`, launcher-ui `src/brand`, `installer/art`, the .ico) still show the old G until the new art lands; the in-game overlay does not draw them (`kUseBrandArt` in `apps/engine/overlay_internal.h`).

## Layout

```

apps/launcher-ui/ the new launcher SPA (replaces the embedded legacy UI when it ships)

apps/ingame-ui/   in-game chat UI                     apps/devtool/   gage_v.exe (CLI inject-chain harness)
apps/server/      gage-server                         apps/bot/       gage-bot

```

## Build (Windows, local toolchain)

Local builds use the portable WinLibs toolchain in `.toolchain/winlibs-gcc13.3` (gcc 13.3, mingw-w64 msvcrt; bundles cmake 3.29 and ninja) and build into `build/win/`:

```bash
export PATH="$PWD/.toolchain/winlibs-gcc13.3/mingw64/bin:$PATH"
cmake -S . -B build/win -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER=x86_64-w64-mingw32-g++.exe -DCMAKE_C_COMPILER=x86_64-w64-mingw32-gcc.exe \
  -DCMAKE_RC_COMPILER=windres.exe
cmake --build build/win --parallel
build/win/selftest/integrity_test.exe "$(cygpath -w "$PWD/build/win/bin")"
build/win/selftest/gage_mp_test.exe
build/win/selftest/game_launch_test.exe
build/win/selftest/legacy_handoff_test.exe  # the one-time RAGE-MP registry clean-up, on a scratch key
build/win/selftest/crash_diag_test.exe   # stack scan, minidump struct, MSVC throw decode, main-thread lookup
build/win/selftest/join_test.exe         # the engine's session adapter against an in-process server, loopback
build/win/selftest/netcode_test.exe      # protocol v1 + server over real ENet on loopback, about 12 s
build/win/selftest/t3_vehvisual_test.exe  # vehicle visual state (v6 tyres / windows / brake lights / steering) + R3 T4 (v7 damage block, sanity layer): wire, store merge, sync modules, real server, about 9 s
build/win/selftest/server_test.exe       # UDP query, master announce, bans, admin channel, about 16 s
build/win/selftest/sync_test.exe         # the remote-player smoother (libs/sync) under loss, jitter and teleports
build/win/selftest/locomotion_test.exe   # remote-ped gait controller against a simulated ped
build/win/selftest/vehicle_drive_test.exe  # remote-vehicle interpolator + drive controller
build/win/selftest/gameplay_test.exe     # v4 pure units: vitals/respawn/hit batcher/emotes/vehicle link
build/win/selftest/brand_apparel_test.exe  # branded-tee texture swap on a WARP D3D11 device
build/win/selftest/present_hook_test.exe   # Present vtable hook + watchdog (fake vtable), then World::HookTick on a real dxgi swap chain next to a simulated re-asserting overlay (the RTSS failure); part 2 needs a D3D11 device (hardware or WARP)
build/win/selftest/ambient_test.exe       # T5: no ambient NPCs / traffic: when it runs (any connection state), the exemption list, sweep planner, breaker, counters
build/win/selftest/pack_sync_test.exe     # launcher car-pack download (signed packs.json, install/update/resume/removal, fake network)
build/win/selftest/pack_profile_test.exe  # per-build car-pack profile (apps/engine/pack_profile.h): Legacy patterns pinned by golden hashes; Enhanced patterns unique at their RVAs in "enhanced EXE/dump and bin/GTA5_Enhanced.exe-*.img" + the read-only pack_enh=1 Round A against a synthetic heap; loud SKIP if the dump is missing (GAGE_REQUIRE_IMG=1 = failure, PACKENH_SHOW=1 prints the simulated log)
# also built: crash_filter_test serverquery_test interest_test quant_test launch_shim_test script_suppress_test
# NEVER run build/win/selftest/*.exe by glob: gage_v.exe there launches GTA.
```

Server only (no Windows client, no WebView2): `cmake -S . -B build/server -G Ninja -DCMAKE_BUILD_TYPE=Release -DGAGE_SERVER_ONLY=ON` (plus the compiler flags above on Windows), then `cmake --build build/server --parallel`. It builds enet, `gage_protocol`, `gage_netclient`, `gage_server_core`, `gage-server` (`build/server/server/`), `netcode_test` and `server_test` (`build/server/selftest/`). `apps/server/CMakeLists.txt` is the standalone entry point for the same set.

Own multiplayer stack (docs/ENGINE-PLAN.md, P1): the C compiler is needed for the vendored ENet (`third_party/enet`, MIT). Build just that part with `cmake --build build/win --target netcode_test gage-server gage-bot`. `gage-server.exe` lands in `build/win/server/` and `gage-bot.exe` in `build/win/tools/`, both outside `bin/` so the installer never picks them up. `gage-server --port N` reads `server.json` (see `apps/server/server.json.example`) and takes console commands `list | kick <id|name> | say <text> | quit`; `gage-bot <host> <port> <name>` walks a circle. The protocol, server and client session sources are portable C++17 (a Linux build of them has not been tried).

- Car packs on Enhanced (docs: memory enhanced-packs-port): `apps/engine/pack_profile.h` holds the per-build `PackProfile` (Legacy = the shipped patterns, byte-identical; Enhanced = patterns derived from the dump), picked by exe name like BuildProfile. `pack_enh` in `HKCU\Software\GAGE-MP` (default 0; 1 = Round A, a READ-ONLY diagnostic that mounts nothing and writes no game memory, `[packenh]` lines in gage.log ending `round A: N of 22 checks ok`; 2 and 3 reserved, log "not built yet"). The logic is `pack_enh_core.h` (pure, tested by `pack_profile_test`), the glue is `pack_enh.cpp` + `pollCodePatches()` in `hook.cpp`.
- `libs/` is the include root of every target: code says `"common/logger.h"`, `"net/serverfinder.h"`, `"protocol/protocol.h"`, `"netclient/session.h"`, `"sync/smoother.h"`, never `../`. A `.cpp` and its own headers use plain `"x.h"`. Tests that `#include` a whole `.cpp` (`tests/gage_mp_test.cpp`, `game_launch_test.cpp`, `integrity_test.cpp`, `crash_diag_test.cpp`) point at `../apps/<app>/<file>.cpp`.
- Default game port is `gage::proto::kDefaultPort` (24800, UDP) everywhere. The server list comes from the master server (`apps/master/`): `kDefaultListUrl` in `libs/net/serverfinder.h` is `http://127.0.0.1:8080/servers` until a public domain exists; `list_url=` in `gage_mp.cfg` overrides it.
- Per-frame hook: the engine ticks from `IDXGISwapChain::Present` by replacing slot 8 of dxgi's swap chain vtable (`apps/engine/present_hook.{h,cpp}`, called from `World::HookTick`), NOT by patching Present's code: RTSS/Afterburner and other overlays patch and re-assert that code, and they killed our inline hook after one frame (2026-11-03, `gage.log` "no frame in the last 10 s (1 in total)"). A watchdog re-takes a replaced slot and installs the old inline hook only if no frame ever arrives, the re-takes run out, or (0.4.30) frames through our OWN slot stopped for `intactStalledMs` 60 s (was 8 s: it patched dxgi in the middle of a GPU hang) (a per-thread guard keeps the tick once per Present). `present_mode` in `HKCU\Software\GAGE-MP` (unset = auto, `0` = the old inline hook only, `1` = vtable only). `gage.log` names the owner of a foreign hook (`hook: Present vtable slot ... held ...`) and the overlay DLLs loaded.
- Remote cars near the local player (R3 T5, docs/sync-specs/vehicle-position.md): drawn at `NetClock::NearT` + the link lag (half our round trip + half the controller's, `Msg::LinkInfo` 44 from the server) instead of the shared-delay lead; `veh_near_clock=0` (HKCU\Software\GAGE-MP) restores round 2's lead, `veh_prox_contact=0` switches the proximity contact path off; server.json `contactLagCapMs` (0 = off) is the arbiter's half-round-trip time correction. The 10 s line to grep is `engine: vehicle position (R3 T5)`. R4 T2 (docs/sync-specs/vehicle-collision-authority.md): a copy opens the contact grace only with a vehicle we control within 10 m (`veh_contact_gate=0` = any contact, as before), and copies extrapolate with the owner's tangential acceleration (`veh_accel_extrap=0` = constant velocity); the lines to grep are `engine: vehicle contacts (R4 T2)` (what the flag touched, the divergence of a copy from its owner at +0.5 / +1 / +2 s after EVERY contact) and the server's per-impact `contact: impact #`. 0.4.30 `veh_ride_free` (default on; `0` = the full 3D correction): a copy's vertical error up to `sync::kRideTolM` (0.25 m) and pitch / roll up to `kTiltTolDeg` (6 deg) are left to its own suspension (pack cars rest at different heights per edition and bounced against the correction); logged as `engine: vehicle ride freedom (0.4.30)`.
- 0.4.30 switches (HKCU\Software\GAGE-MP; each default on, `0` = the 0.4.29 behaviour): `veh_omega_guard` (no derived omega from a standing pair or across sources into a standing owner: parked copies stopped spinning), `veh_lights_beam_lit` (a high beam reads lightsOn 0 / highbeamsOn 1: either bit = lit), `veh_siren_horn` (siren on + E held 150 ms sends the horn bit; a tap is GTA's siren-mode switch), `veh_steer_field` (copies steer through the CVehicle steering-angle field, `apps/engine/veh_fields.h`, resolved by pattern after two agreeing scans, every write behind a vtable-in-image and plausible-angle check; `hook: [vehfields]` names the result; EXCEPTION to "default on": unset = auto = Enhanced only (dump-proven), Legacy needs `veh_steer_field=1` until a live run proves its patterns), `anim_phase_fix` (TASK_PLAY_ANIM's 8th argument is the START PHASE: 0, not 1.0), `stagger_clip` (a melee stagger is the `reaction@shove` clip, never a ragdoll), `hyper_yaw` (the yaw cap is a spin guard: 50 / 32 m/s^2 from 45 / 35 m/s). `melee_survey` and `melee_loop` now default to off.
- 0.4.31 switches (HKCU\Software\GAGE-MP; default on, `0` = the 0.4.30 behaviour): `hud_ring` = GI's Claude Design HUD (`HUD_DESIGN_COMPONENTS/REV1` vitals ring bottom-left with GTA's radar HIDDEN, GI's choice "exact spot, map hidden"; `REV2` car cluster bottom-right: dial, fuel arc, blinkers, lock / engine / belt / headlight chips). Pure numbers and rules in `libs/sync/hud_ring.h` / `hud_car.h` (pinned to the specs' tables by `tests/hud_ring_tests.h` / `hud_car_tests.h` in gameplay_test), drawing in `overlay_ui.cpp` `DrawVitalsRing` / `DrawCarCluster` with the embedded Sofia Sans Bold (`brand/fonts`, OFL). Grep `overlay: vitals ring` and `engine: HUD (0.4.31)`. `accel_curve` = `sync::AccelPowerAt` (libs/sync/hypertune.h): the tuned cars' cheat power falls with speed (x4.9 to 60 km/h on a 500 km/h hyper, the old flat power at 30 % of top speed, a floor of 60 % / stock above); grep `engine: acceleration curve (0.4.31)`. The hyper tune is 500 km/h again and the server's `vehicleMaxSpeed` default is 139 m/s (a server.json that pins 170 keeps 170; the live VPS server.json was set to 139 on 2026-11-06, backup `server.json.bak-20261106-vmax150`).
- 0.4.32 (clean-up round, no new switch): the quit card is shared by both overlay backends (`detail::QuitGate` in overlay.cpp; before, Alt+F4 on Enhanced/DX12 went to GTA's pausing quit screen and the server saw a timeout instead of a leave). HUD fidelity: CSS group-opacity fades (glows cut out under their shapes), crisp 1 px pill and chip borders (ImGui's AddRect / AddCircle already inset by half a pixel), the speed numeral centred in cell minus tracking, small faces baked with RasterizerMultiply 1.22. Retired, unbuilt sources live in `docs/archive/engine-retired/` (loading_screen, dlc_mount) and `docs/archive/launcher-retired/` (wv2_shims). 0.4.33 (second pass, no switch): `vehFieldPtr` (hook.cpp) checks the object, its vtable and the field with ONE VirtualQuery and reports writability (the steering write and the copy-controls read used to query again per call); a field outside the object's region falls back to its own query. `net::Ping` and `VersionAtLeast` are gone (no callers; `FetchVersion` stays for update_check_test). 0.4.34 (shipped as 0.5.0, GI's version bump; GI after the first live look): the ring is drawn at `hudring::kSize` 0.75 and the car cluster at `hudcar::kSize` 0.5 of the design, each about its own outer corner (the 56 px margins stay); `Scale(H)` = `DesignScale(H)` x kSize, every position goes through `ToScreen` (the strip text did not, and drifted), and the Sofia faces and icon glows are baked at the drawn size.
- Launcher -> engine handoff is `HKCU\Software\GAGE-MP`: `server_host`, `server_port`, `player_name` (written by `DoLaunch` in `apps/launcher/gage_gui.cpp`, read by `Run()` in `apps/engine/gage_mp.cpp`). The launcher no longer touches `HKCU\Software\RAGE-MP`; a one-time clean-up (`apps/launcher/legacy_handoff.cpp`) removes only the values older GAGE-MP versions wrote there, and only when `rage_path` points into this install.
- The UI embedded into `SolarLauncher.exe` is `apps/launcher-ui/dist/index.html` (`GAGE_UI_HTML_IN` in `CMakeLists.txt`; run `npm run build` there with Node 22.12+ first). Its 3D set `dist/assets` is copied post-build to `build/win/bin/launcher-assets/` and served under `https://app.gage/assets/` only for paths in its `manifest.json`. With no platform API (`-DGAGE_API_BASE=` or `api_base=` in `gage_mp.cfg`) the exe opens the UI as `?demo=1`: labelled demo data, real bridge, launch refused with code 13. Still to wire (NATIVE-INTEGRATION.md 3.2-3.4): `launchStage`, `joinTokenNeeded`/`joinToken`, `game`, `deepLink`, code 12. The legacy SPA's recovered build stays in `docs/archive/web-legacy/dist/`.
- `third_party/webview2/x` holds the Microsoft.Web.WebView2 1.0.2903.40 NuGet package (headers only).
- Installer: `BIN="$PWD/build/win/bin" bash installer/build-installer.sh` (Inno Setup 6.7.3 portable in `.toolchain/innosetup-6.7.3`) -> `build/win/installer/SolarRP-Setup-<kClientVersion>.exe` (AppName "Solar RP"; a new install defaults to `{autopf}\Solar RP`, an upgrade keeps the previous folder, removes `GAGE-MP.exe` and the old "GAGE-MP" shortcuts, and creates the "Solar Launcher" shortcuts). It packages the exe, the 3 chain DLLs, `gage_launch_shim.dll`, `ui/` and `launcher-assets/` (the launcher UI's 3D video set). The 0.2.5 setup is 18.5 MB (built 2026-10-31): `launcher-assets/` is ~12 MB of already-compressed video, the exe + 4 DLLs ~7.5 MB, `ui/` tiny. `[InstallDelete]` removes the old `{app}\rage` runtime and `gage_eac.dll` on upgrade.
- SolarLauncher.exe bakes the SHA-256 of all 3 chain DLLs (`gageinjector.dll`, `gage_loader.dll`, `gage_mp.dll`): ship the exe and all 3 DLLs together.
- `docs/archive/assets/` holds the retired RAGE-MP client-asset downloader (not built); its README says how to bring it back.
