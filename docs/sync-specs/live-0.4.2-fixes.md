## W8: on foot, combat, server config visibility

1. **Server: no silent pins.** At Server::Start log the effective ReplConfig (already partly logged), plus playerHealth and every damage percentage. In Config validation (config.cpp ~193) WARN (not fail) when `rateNearHz < tickHz`, naming both values and the effect ("players reach each other at N/s, not tickHz/s"). server_test: load `{"tickHz":30,"rateNearHz":20}` and assert the warning text. Also make deploy-server.sh print the same warning by reading `server.json` before activation (do not rewrite the file).
2. **Smoother class-extra hysteresis.** `ClassExtraMs` / `ClassDelay` (libs/sync/smoother.cpp:131-138, TypicalGapMs takes the upper median): add hysteresis so a stream whose gaps alternate (33/33/67, or jitter around a boundary) does not flip k up and down; the render time slewing at 10% each flip is a speed ripple. Test: a 20 Hz-pattern stream with jitter changes its extra at most once per minute after settling.
3. **Locomotion churn.** On-foot windows show 10-21 GoStraight re-issues per 10 s (target <= 0.4/s going straight). (a) Add per-trigger counters to the 10 s sync line: turn, drift, arrive, stall, and Reset with the caller site. (b) `pe.loco.Reset()` is called from ~12 sites in engine.cpp (3120, 3332, 3459, 3487, 3505, 3517, 3533, 3547, 3572, 3594, 3623, 3647) and each Reset re-issues the task at once: split into a soft reset (re-evaluate, keep the running task if it still points within the turn threshold) and a hard reset (only on teleport, respawn, vehicle exit, resync); classify each call site. (c) The velocity push at engine.cpp:3769-3780 over TASK_GO_STRAIGHT_TO_COORD with move-rate clamp 0.8-1.25: make the move-rate match the pose speed for the current gait so the anim and the displacement agree (less slide), and only push velocity for the residual error, low-passed. Test in locomotion_test: a straight run at constant speed with 33 ms samples + 20 ms jitter issues <= 1 task per 2.5 s and no Reset-triggered re-issues.
4. **Swimming (remote).** The receiver only passes `in.swimming` into the loco controller (engine.cpp:3673); a swimmer is driven by the land-gait task plus velocity push. While the sender's kPfSwimming is set: no land-gait task, let GTA's swim locomotion follow a go-to-coord with the swim speed, position correction via the same residual push but tuned for water (no ground snap, keep Z from the sample, allow underwater). Make entering/leaving water an edge that does a soft reset. Test the edge logic purely.
5. **Vault / climb / jump.** No IS_PED_VAULTING anywhere: vaults and slides over cars set no flag, so the puppet is pushed through and snaps. Add sender flag kPfVaulting (next free bit in the PedState u16 flags; document it in docs/api/protocol.md as a v5 addition with no version bump) from IS_PED_VAULTING. Receiver: on the rising edge of vaulting or climbing, issue TASK_CLIMB once (edge-triggered, like the TASK_JUMP edge at engine.cpp:3702) and suspend position correction and the velocity push until the flag falls (+ a short settle), then a soft reset. Today climbing turns collision off and places the ped on the pose (engine.cpp:3542 airPlaced, :3632): keep that only as the fallback when the task fails to start within ~300 ms. Pure test for the edge/suspend window.
6. **Real peer gunfire (sound, tracers, muzzle).** Default `peer_shoot` to the real-fire path (`SET_PED_SHOOTS_AT_COORD` with SET_PED_INFINITE_AMMO_CLIP, weapon equipped; path exists at engine.cpp:2862-2874), keep the script-bullet path as `peer_shoot=script` fallback. At Welcome call SET_AI_WEAPON_DAMAGE_MODIFIER(0.0) and SET_AI_MELEE_WEAPON_DAMAGE_MODIFIER(0.0); on session end call both RESET natives. Remove the `ShotLineClear` restriction for the real-fire path only if the damage modifiers are applied (log it). Keep the existing puppet-loss / local-health guard and add a counter "local health changed by puppet fire" to the combat line so the live test proves damage stays 0. Server damage stays authoritative and unchanged.
7. **Dead-puppet pool damage.** ProbePeerDamage (combat.cpp:309-316) reports `pool - health` for a puppet that died locally ("one blow above the 1000 pool"), i.e. nearly the whole pool as one hit: that made 2-punch kills. Cap the reported damage to the weapon's nominal maximum (or 0, letting the server decide) when the puppet is dead/ragdolled by a non-weapon cause. Test that fails today: `ProbePeerDamage(health<=0, pool=1000, byMe, dead, unarmed)` must not report ~1000.
8. **Alt-tab.** While GTA is unfocused, scripts stop (`GameWork 0.00 ms over 0 script tick(s)`), Present keeps running and the render-thread fallback sends a DEFAULT PedState (weapon 0, idle, no flags, engine.cpp:5990); join.cpp keep-alives repeat it. Fix the sender: when no script tick ran, send the LAST real PedState with velocity zeroed and move set to idle/still (keep weapon, vehicle, seat, flags except transient ones), and mark nothing else. Fix the receiver: when a peer's state turns still after running, settle to the last pose (no 1.5 m extrapolated hold: cap extrapolation when the next sample says speed 0); make sure a cleared kPfClimbing/kPfParachute restores collision and that a stale `pe.aimTask` is cleared on weapon 0 / still. Add to the 10 s sync line: last applied flags, move, weapon, the latched loco task, collisionOff. Pure tests for the sender fallback selection and the receiver settle.

## W9: vehicles, passengers, collision (after W8)

1. **Passenger enter on the other screen.** Local F entry warps (engine.cpp:4951 SetPedIntoVehicle, by design). The puppet side starts TaskEnterVehicle on move 5 (engine.cpp:3482) and then waits for `EnterWarpDue` (engine.cpp:4636-4640, pedstate.h kEnterTaskMaxMs 2500) before warping, so the other screen shows a 2.5 s door walk while the real passenger is seated in 0.3 s. Fix: EnterWarpDue returns true as soon as the sender's latest move is no longer kMoveEnteringVehicle and the server lists the seat. Test that fails today: `EnterWarpDue(serverSeated=true, locallySeated=false, since=300, senderStillEntering=false) == true`.
2. **Seat shuffle loop.** PCF 184 (PreventAutoShuffleToDriversSeat) is set only on the local ped (engine.cpp:4984). Set it on every puppet at seat time (SET_PED_CONFIG_FLAG). A puppet that GTA shuffles makes the seat loop re-warp every 100 ms (engine.cpp:4620-4650): log re-warps per 10 s and rate-limit them.
3. **Double F / enter-exit loop.** GI's log 10:47:03-08: enter, exit 1.4 s later, enter, exit, enter. Verify whether GTA's own INPUT_ENTER (control 23) consumes the same press once seated; disable control 23 for the frame of our handled press and for ~500 ms after seating, and log handled presses.
4. **Passenger engine sound.** The engine flag is applied only on change (engine.cpp:4351-4356, SET_VEHICLE_ENGINE_ON(veh,on,instantly=1,disableAutoStart=0)) from kVehEngine read by the controller (:5259); the server clears it at 0 fuel (vehicles.h:464). For the car the LOCAL ped sits in as a passenger: re-assert engine on every ~1 s while the server says engine on, and set the puppet driver's throttle/RPM audio if a native exists (look it up; e.g. SET_VEHICLE_CURRENT_RPM / audio natives), otherwise log what was tried. Log the engine state of the local passenger's vehicle on the 10 s vehicles line.
5. **Exit at speed (bikes and cars).** UnseatPeer (engine.cpp:4223-4252) uses TASK_LEAVE_VEHICLE(ped, veh, 0), which does not bail out of a moving vehicle; loco.Pause then suspends control for kUnseatPauseMs. If the vehicle speed > ~3 m/s or the sender's first on-foot sample has kPfRagdoll/kPfFalling/kPfJumping: use flag 4160 (bail out; 16 = warp out as fallback), apply the existing ragdoll edge, give the ped the vehicle's velocity for the exit window, and suspend position correction until the sender's ragdoll ends. Pure test for the decision. Same for the local player's own exit on a bike: check what the F handler does at speed and make it a bail-out, not a warp.
6. **Collision, part 1 (no protocol change).** Remote cars get velocity, angular velocity and quaternion written every frame (engine.cpp:4568-4590), so any impulse is overwritten within a frame; puppets spawn with SET_PED_CAN_RAGDOLL false (engine.cpp:3114, 3692), so car hits never ragdoll them.
   - **Contact grace:** detect a contact on a remote car (HAS_ENTITY_COLLIDED_WITH_ANYTHING or a measured velocity change the controller did not command) and, for ~400 ms, blend the correction from full to soft (lower gains, no snap) so the crash plays out, then converge back. Pure test in vehicle_drive_test.
   - **Present-time prediction within ~30 m:** for remote cars within 30 m of the local player, render at present time (extrapolate by the render delay with the sample velocity, capped) instead of ~110 ms in the past, blending back to the interpolated time beyond ~45 m. Pure test: a car moving at 30 m/s is shown within 0.5 m of its true present position at 20 m distance.
   - **Puppet ragdoll on vehicle impact:** allow ragdoll on puppets for vehicle impacts (SET_PED_CAN_RAGDOLL true only for that cause, or SET_PED_TO_RAGDOLL on a detected hit by the local player's vehicle above ~5 m/s), suspend position correction until the sender's next state (the owner is authoritative; their ragdoll arrives via the Tier B edge). Impact events to the victim's owner are 0.4.4.
7. **Bikes.** No bike-specific handling exists; bikes are driven like cars. The quaternion carries lean, so first verify (pure, in vehicle_drive_test) that roll is preserved through the controller; add a 10 s log line per remote bike (roll error, speed, corrections) so the next live test shows what is wrong. Do not invent lean physics without evidence.
8. **Hit rate on drivers:** log, per 10 s, shots at seated peers and hits sent on them, so the next test shows whether seated puppets are hittable.
