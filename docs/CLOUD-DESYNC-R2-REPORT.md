## 1. Peds slide; animations not in place (T2)
**Root cause (evidence level: simulation of 40 game-behaviour models; the true model is unknown).** The 0.4.6 default closes the position error with a `SET_ENTITY_VELOCITY` residual push and steers with `TASK_GO_TO_ENTITY` on an invisible frozen anchor ped, and it is only right if the game REPLACES the velocity and follows the anchor. T2's matrix (`T2_EXPLORE=1 T2_SWEEP=1 locomotion_test`: go-to-entity follows / 60 % / never moves; velocity replaces / adds / ignored; move-rate scales / ignored; arc / pivot turns; stride x1 / .85 / 1.15; 12 scenarios) gives p95 error 0.47 m when the game is as assumed and 1.48 m averaged over the 30 models where it is not (velocity "adds": gait changes skate 13.8 % / p95 1.37 m; "ignored + rate ignored": p95 4.9 m). Nothing in 0.4.6 noticed a go-to task that runs but carries nothing, an ignored move rate, or repeated snaps. The old "reversal" row (20 % skate) was an artefact (it flipped at full speed); a realistic stop-turn-go: 0.4.6 29 % skate / 2.2 m (velocity adds) or 8.9 % / 1.09 m (replaces), T2 8 % / 0.55 m. T0: in STRAIGHT mode the controller re-issues identically at 0.4.3, 0.4.5 and HEAD, so what changed for GI is the anchor/closed-loop glue.
**Fix.** `PushMode::Nudge` (SET_ENTITY_COORDS_NO_OFFSET, dead band 0.12 m moving / 0.25 m standing, tau 250 ms, cap 3 m/s) replaces the velocity residual on foot (jump/ragdoll/swim keep velocity); own-speed measurement net of our writes; a degradation ladder Full -> Straight -> NoRate -> Placed with MEASURED triggers (ped reads no gait; own speed < 35 % of pose for 1.2 s or 3 snaps in 6 s; nudge > 10 % of distance in 3 s of steady motion; rate-slope < 0.25; two straight stalls in 15 s), doubling recovery timers, and a witness rule (two different puppets degrade => all); fast Run->Walk down-shift; `oneshot.h` audit of jump/reload/stealth/swim/ragdoll (asked vs read back). Switches (HKCU, read at Welcome): `loco_mode=straight`, `loco_push=velocity`, `loco_selfcheck=0`.
**Failing-on-old.** `locomotion_test` 77 -> 98: every bound is paired with the 0.4.6 config violating it; "no level change in a working game" (228 runs) is paired with the dead / sluggish / rate-ignored / no-move runs that DO change level. 12 mutants (nudge off -> 8 fail; ladder off -> 5; fast down-shift off, own speed not net of nudges, steady-motion gating removed, witness accepts same puppet twice, dead band 0, nudge cap removed, rate-slope trigger off, ...), each caught.
**Live-unverified, GI steps.** 60 s with a friend: walk / run / sprint / stop-and-go / U-turns, four runs: (1) default; (2) `loco_mode=straight`; (3) `loco_push=velocity`; (4) `loco_selfcheck=0` only if 1 misbehaves. Grep `gage.log`: `engine: loco slide id=` (new "| T2:" tail), `engine: loco level id=` (each ladder step + reason), `engine: anims onfoot (T2)`, startup "position error closed by ...". Healthy = level 0, skate < 5 %, nudge share < 5 %, own speed within 10 % of pose, error mean < 0.3 m / max < 1 m, rate at a limit < 30 % of frames, ped-anchor distance ~ the lead (1.2 m walk / 3.6 run / 5 sprint). Decision rules: anchor lost/stuck/dragging in a puppet's first seconds => go-to-entity does not follow the frozen anchor => ship `loco_mode=straight`; "rate-ineffective" => drop the rate loop; walking own speed ~0 under default but fine with `loco_push=velocity` => the per-frame coordinate write breaks the walk animation => ship `loco_push=velocity`.
**What's weak.** All numbers are against simulated models; the nudge assumes a per-frame coordinate write on a ped under a task does not disturb its walk animation / ground probe; detection takes 2-5 s per puppet; straight mode has no model risk but keeps 6-9 task re-issues per 10 s; sluggish + ignored-rate cases still skate 14-35 % until the ladder acts; instant reversals/teleports are physically unfollowable. **Animations: no state was found that both needs a new wire field and can be played with an available native, so no PedState field was added.** Genuinely missing: ladders and parachute (natives needed below), swim (no swim task; relies on the game), standing turns use a hard heading set. Cost of `anchor + ladder default` is a judgement (break-even if go-to-entity works with probability > ~40 %).

## 2. Vehicle enter / exit / seats (T1)
**Root cause (code + pure test).** The local player never animates: `TickVehicleEntry` disables controls 23/47, runs to the door with `TASK_GO_STRAIGHT_TO_COORD` and `SetPedIntoVehicle`s from <= 1.6 m (teleport-in). The wire had no intent (PedState move 5/6 is a snapshot, `VehicleWorld.seats` only says who sits). Receivers popped the puppet in when the seat list named it (0.4.6 `puppet_enter=follow`; W9's `EnterWarpDue` had cut the earlier door walk short).
**Fix.** The server RESERVES a seat on `EnterIntent` (TTL 6 s, conflicts -> `SeatTaken`, owned-car driver seat -> `NotOwner`, Exit-while-reserved cancels, vehicle despawn / player gone / death cancel) and broadcasts `SeatNotice`. The local client issues GTA's real `TASK_ENTER_VEHICLE` (flags 1, no jack flag) for exactly that seat after the server's Ok; every other client replays the same task once on the puppet; the seat warp waits 1.5 s after `Seated` while the task runs and is otherwise only a bounded fallback (task never started 1 s; stopped without a seat 0.4 s after; time limit door 4.5 s / bike-cycle 3.5 s; no answer 2 s => cancel, no teleport). Exit: the `Exited` notice runs the exit animation at once, a 700 ms latch refuses a stale seat list; a puppet seated by its task but never named by the list is evicted after 2.5 s. Entry style is NOT on the wire (the game picks the animation from seat and car; each client reads the car class). Vault/slide-over is T2's generic on-foot climb, not a seat matter. `seat_intent=0` restores the old entry.
**Failing-on-old.** `tests/t1_seats_scenario.h`: one three-client script (reserve/refuse/cancel/exit/despawn/bike pillion/timeout fallback/never-ending task) run against the real `VehicleStore` behind a 40 ms relay (gameplay_test) AND against the real server over ENet (netcode_test); a legacy-client model ends in the right seat with 0 tasks and 1 warp per observer and is rejected; each "no warp" check sits beside "task issued exactly once". 12 mutants (enter ignores reservation, reserve ignores holder, grace 0, latch 0, exit-pending not cancelled, cancel keeps task, destroy keeps intents, local warps at once, no Seated notice, supersede keeps task, NeverStarted ignored, issue twice), each caught. gameplay_test +56, decode_fuzz +30, netcode +20.
**Live-unverified, GI steps.** Two+ players on the new build, a car, a passenger seat, a bike: F next to a car (walk/run to the door with the game's enter animation, no teleport); the other screen shows the puppet playing the enter task and seated by the game; a second player pressing F toward a reserved seat is told it is taken; cancel mid-enter (F again / walk away); exit shows the normal exit animation on the other screen; locked-car owner path still teleports (expected); A/B with `seat_intent=0`. Grep `engine: seats (T1), last 10 s:` (task issued / running / finished with us seated / never started / stopped without a seat / timed out, `FALLBACK WARPS`, `DIVERGENCES`), `engine: seats: FALLBACK WARP`, `engine: seats: DIVERGENCE`, server `seats: last 10 s:`. Healthy: `FALLBACK WARPS 0`, `never started 0` on both screens. A large `never started` => the game does not name a scripted enter task through TRYING_TO_ENTER/USING => the fallback fires ~1 s after F mid-animation => use `seat_intent=0`.
**What's weak.** The whole animation path rests on `TASK_ENTER_VEHICLE` (seat index, speed argument, no jack flag) behaving as assumed on the player and on a puppet and on its readback via `GET_VEHICLE_PED_IS_TRYING_TO_ENTER` / `GET_VEHICLE_PED_IS_USING`; if not, it degrades to a visible late pop. No cancel-by-movement. A client that streams the car in mid-enter gets no replay (falls back to the seat-list warp). Locked-car owner entry has no animation for others. Bike pillion = wire seat 1 = GTA seat 0 and bike seat bones are probably missing (door positions use +-0.45 m offsets). The glue (`TickPeerSeatReplay`, `HandleSeatNotice`, the seat-loop gate) is compile-checked only.

Wheel spin is not synced; a game-applied brake on a task-less copy is a hypothesis.

## 4. Ambient NPCs and traffic (T5)
**Root cause (code, proven by reading).** `SuppressAmbientFrame` was called only inside the entry wait and after `if (!EnterServer()) return;`; the 5 s `SuppressSPSystems` block sat behind the same gate and behind `mayChange`; so nothing ran offline, while connecting, during join retries (every 5 s), after "session ended" or when the script tick was not live (render fallback with default spawn mode -1). Every return value was ignored (an unresolved hash looked exactly like "NPCs still appear"); `ClearAmbientAround` ran only at entry and respawn; `_THIS_FRAME` multipliers only stop NEW spawns and nothing swept existing entities.
**Fix.** New pure `apps/engine/ambient.h`; `TickAmbient` runs at the top of `GameWork` before the local-ped check and the `EnterServer` gate, on the script tick and on the render fallback, in every connection state (per-frame multipliers every tick; persistent switches every 2 s; area clear every 3 s, 200 m; sweep every 1 s). Per-native call/failure tally with first-use flags, the exemption list (local ped; every `g_peers` ped and anchor; every `g_vehs` handle; `g_companion`; `/car` vehicles; the local player's current and last vehicle) as a tested predicate `MayDelete` that refuses everything on an incomplete list, a circuit breaker (any exempt entity lost around a clear/sweep switches clears and sweeps off for the process and logs a WARN), kill switches `ambient`, `ambient_render`, `ambient_clear`, `ambient_sweep`. The old area-clear call sites go through the breaker too.
**Failing-on-old.** `ambient_test` (new exe, soft because it reads engine.cpp by path): the source-order guard fails on HEAD (no `TickAmbient` before the gate; `SuppressAmbientFrame` called from 2 places); a 60-tick/s session replay (old rule covers 1800 of 3600 ticks, new scheduler all); a 2000-random-world property test (no exempt handle ever planned, 8069 exempt handles protected); 8 mutants incl. breaker never trips (3 fail), MayDelete ignores completeness (3), exempt check removed (3), counters removed (7), hash 0 reaches CallNative (3).

## 5. Health sticks at 50 (T6)
**Root cause (reproduced through the REAL server + client session + tracker; the sim ped is a model).** Units are consistent (server playerHealth = hit points above the death line, Welcome u8 with no clamp, ped max = 100 + playerHealth = 300, HUD = (hp-100)/(max-100)); a bar at 50 % is a real ped 200/300 and a server that really holds 100 of 200. The trigger: `TickEntryGuard` calls `SetPlayerModel` => a NEW ped at GTA's default 200/200; `ApplyServerMaxHealth` raises the max to 300 in the SAME script tick; the next `VitalsTracker::Tick` sees 300 -> 200 with max unchanged = an unexplained loss of 100 and reports a **self-hit of 100**; the server accepts it (200 -> 100) and the ack puts GTA 200 on max 300. Server has no regen, client regen is off, so it sticks. Exact old-code output: `ped 200/300 bar 50% server 100 self-hits 1 (100)` (playerHealth 200); hurt 40 first: self-hit 60; playerHealth 255: bar 39 %; playerHealth 100 is harmless (max 200 = default) which is why it started when the VPS moved to 200. The 0e fix (b3dcf3e) covered only an OBSERVED max change. Secondary defects fixed: a max read of 0 made the tracker substitute 200 and draw a 0.00 bar; `OnWelcome` stored `g_playerHealth` ~30 lines after raising `g_v4Reset`.
**Fix.** `VitalsObs::ped` handle (a changed handle = new ped: baseline + put the server value on it, never a loss), `NotePedReplaced()`, an ABSOLUTE reconciliation (living steady ped 1 s off 100 + expHealth, nothing pending, no puppet in play => re-apply, 3 tries per mismatch then `reconcileGaveUp`), an unreadable max (<= 100) keeps the last good max, `ApplyMaxHealth` with read-back, `HudHealthFraction` fallback. New `engine: health:` 10 s line, WARN on any self-hit >= 50 with no fall/puppet cause, swap and `SET_ENTITY_MAX_HEALTH` read-back logging.
**Failing-on-old.** `tests/t6_health_tests.h`, 29 pure + 18 network checks through the real server over ENet (playerHealth 100 / 200 / 255 across join, swap at full health, swap after damage, fall, fall after swap, shot / heal / kill / respawn, reconnect 100 -> 200 -> 255). Run against the real pre-fix `combat.*` (`-DT6_BASELINE`): pure 12 fail, network 5 fail; **I reproduced it independently: with 4e2ef63's combat.* and `-DT6_BASELINE`, gameplay_test fails 12 of the new checks (420/432), including `ped 200/300 bar 50% server 100`, and passes 432/432 with the fix.** Presence checks next to every absence check (a 30-point fall is exactly one self-hit of 30 at all three playerHealth values; a fall after a swap and during a late ack is still reported). 7 mutants on scratch copies, all caught.

Manual: a fall or shot to ~60 %, `/heal` => 100 %; die and respawn => 100 %; reconnect => 100 %.

That the guard swap fires on GI's machine is not shown by any log. ## 6. Car-to-car collision desync (T4)
**Root cause (new two-machine simulation `tests/vehsim_2m.h`: N machines, each with planar physics for its own cars and a velocity-overwritten copy of the others through the REAL interpolator, drive controller, PresentLead, NetClock, ClassDelay, server relay, quantisation, loss and jitter, graded against a one-physics-instance reference).** Today, 1 s after the reference contact (average of 6 seeds, worst car): head-on 20+20 position error 11 m (18 m / 12 m on 90 / 120 ms links), rear-end 5.3 m, into a parked car 4.1 m, two cars into a parked third 31.8 m after 3 s; real cars interpenetrate by up to 2 m at the same global instant. Mechanism: the copy is a WALL THAT KEEPS COMING (the next frame re-commands it to the stream's pre-impact velocity, so the local car is hit again every frame for the whole network latency and thrown back ~3x too hard); the contact grace softens but pulls the copy back to the stale stream; a parked car is a copy for everyone except its last driver so the rammer hits a wall; a velocity update over 150 m/s was BadArg and froze a hyper car for everyone else. T0's "5-7 m contact-position disagreement" was NOT reproduced as the dominant effect (with PresentLead inside 30 m the contact spread was only 1-130 ms).
**Fix (the best-in-slot trade-off, one paragraph).** Resolving every contact on one machine (a "host" simulating both cars) would be the most physical result, but it needs the other driver's inputs, which live only on his machine, and GTA physics cannot be rolled back; the host would also show the guest's car steered by a copy 100+ ms stale, so that candidate was not built. Each controller keeps its own physics for its own car (the player's car never rubber-bands under his hands), and the three removable divergence sources were removed: (1) the copy is no longer a wall: its own physics response is ADOPTED as its trajectory (`ReplaceFrom` refuses the stale stream until a pushed sample shows the impact or 300 ms pass), so each machine simulates a closed two-body system from nearly identical states; (2) the server computes ONE momentum-conserving result from both exact tracks on one clock (`ContactArbiter`: per-vehicle 8-sample tracks on the SampleClock base, first instant the boxes grown 0.3 m touch, bisected, pre-impact velocities, one planar impulse by mass class, restitution 0.25, friction 0.3, once per contact with a graze rule, closing-speed floor and |dv| <= 30) and sends each controller its half in `VehicleImpact` with the contact time on that controller's own clock; the client writes (authoritative change minus what its game already did) onto velocity and yaw rate, a bounded residual, not an authority (a client can only drive its own track; untrusted controllers are skipped; the server never moves a car it did not see touch); (3) a driverless vehicle moves to the rammer's machine before the hit (empty-car claim: `claimBaseMeters 10, claimLookSeconds 0.5, claimMinSpeed 3, claimHoldMs 1500`), so the pair is one physics instance.
